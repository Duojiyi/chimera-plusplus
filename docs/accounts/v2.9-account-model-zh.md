# v2.9 官方账号数据模型（后端落地版）

> 范围：Codex 官方账号（`AppType::Codex` 的 official 线路）的**元数据**能力。
> 本轮只改 Rust 后端，前端一行未动；本文件是前端落地阶段的对接契约。
> 相关源码：`src-tauri/src/commands/official_accounts.rs`、`src-tauri/src/official_account_meta.rs`、
> `src-tauri/src/services/official_quota_cache.rs`、`src-tauri/src/database/dao/official_accounts.rs`、
> `src-tauri/src/database/schema.rs`。

---

## 1. 为什么这么放（设计取舍）

账号实体原来太「瘦」：`OfficialAccountDto` 只有 14 个字段，全部从加密 slot + 线路 pin 现算。
结果每进一次账号页都要现查配额，列表也没法检索、分组、批量操作。

真正的凭据仍然只存在 `codex_accounts::vault` 里（DPAPI 信封 + owner-only DACL + 版本化格式）。
**本轮没有往信封里加任何字段**：信封一动，丢的就是用户要重新登录一次的凭据。

新增的东西全部落在 SQLite，按 **account key** 关联：

| 位置 | 存什么 | 属于 |
| --- | --- | --- |
| `vault`（加密信封，未改） | 令牌、邮箱、线路身份 | 凭据（不能碰） |
| `official_account_meta` | 标签、分组、备注、停用标记、最后使用时间 | **用户数据**（进备份文件，不进云同步） |
| `official_account_groups` | 分组名、颜色、排序 | **用户数据**（进备份文件，不进云同步） |
| `official_account_quota` | 最后一次配额读数 | **本机缓存**（易失，不进备份/同步） |

标签与分组**留在本机**：登录本身（vault）从不同步，停用与最后使用时间也是这台机器的事实。
所以两张表在 `SYNC_SKIP_TABLES`（上传时不带）和 `SYNC_PRESERVE_TABLES`（下载时保留本机的行）里，
从别的设备或还没有这两张表的旧版本下载，都不会抹掉本机的标签；备份文件的导出与恢复照常包含它们。

按 account key 而不是「账号 id」关联，是为了让标签在**重新登录**后仍然跟着同一个账号：
slot 可能被重建，key 不变。

## 2. 数据模型

### 2.1 `official_account_meta`（用户数据）

| 列 | 类型 | 语义 |
| --- | --- | --- |
| `account_key` | TEXT PK | 账号 key（与 vault slot 同名） |
| `tags` | TEXT NOT NULL DEFAULT `'[]'` | JSON 字符串数组，已规范化 |
| `group_id` | TEXT NULL | 所属分组；NULL = 未分组 |
| `note` | TEXT NULL | 用户备注，≤1000 字符 |
| `disabled` | BOOLEAN NOT NULL DEFAULT 0 | 用户主动「停用」 |
| `disabled_at` | INTEGER NULL | 停用时刻（ms） |
| `disabled_reason` | TEXT NULL | 停用原因，≤200 字符 |
| `last_used_at` | INTEGER NULL | 最后一次被 Codex 使用（ms） |
| `created_at` / `updated_at` | INTEGER NULL | 行时间戳（ms） |

索引：`idx_official_account_meta_group ON official_account_meta(group_id)`。

**没有行 = 全部默认值**。所有写命令都是 upsert，第一次打标签才建行。

### 2.2 `official_account_groups`（用户数据）

| 列 | 类型 | 语义 |
| --- | --- | --- |
| `id` | TEXT PK | `group-<uuid>` |
| `name` | TEXT NOT NULL | 分组名，≤40 字符，非空 |
| `color` | TEXT NULL | `#RGB` / `#RRGGBB` / `#RRGGBBAA`，小写 |
| `sort_index` | INTEGER NOT NULL DEFAULT 0 | 用户排序 |
| `created_at` / `updated_at` | INTEGER NULL | ms |

删除分组**不删账号**：同一事务里把成员的 `group_id` 置 NULL，再删分组行。

### 2.3 `official_account_quota`（本机缓存）

| 列 | 类型 | 语义 |
| --- | --- | --- |
| `account_key` | TEXT PK | 账号 key |
| `payload` | TEXT NOT NULL DEFAULT `''` | 整个 `SubscriptionQuota` 的 JSON |
| `fetched_at` | INTEGER NOT NULL DEFAULT 0 | **最后一次成功**读数时刻（ms）；0 = 从未成功 |
| `last_attempt_at` | INTEGER NOT NULL DEFAULT 0 | 最后一次尝试时刻（成功或失败） |
| `access_expired` | BOOLEAN NOT NULL DEFAULT 0 | 本地令牌已过期 |

**这张表不进导出、不进云同步**：`src-tauri/src/database/backup.rs` 里
`EXPORT_SKIP_TABLES` / `SYNC_SKIP_TABLES` / `SYNC_PRESERVE_TABLES` 都加了 `official_account_quota`。
理由：配额是「此刻这台机器看到的用量」，从别的设备同步过来的读数会误导用户；
`SYNC_PRESERVE_TABLES` 是为了让同步导入不要清掉本机缓存。

### 2.4 语义约定（容易搞反，务必看）

- **`utilization` 是「已用百分比」0–100**（沿用本项目 Claude 侧 `claude_accounts/quota.rs` 与
  `services/subscription.rs` 的既有语义）。上游 cockpit-tools 的 `percentage` 是「**剩余**百分比」，
  两者相反。本项目的排序 `sort=quota` 用的是 utilization，**升序 = 用量少（余量多）在前**。
- `disabled` 只是**标签**，不动凭据：不删除、不解密失败、随时可恢复。
- `is_current`（Codex 此刻在用的）/ `is_selected`（当前线路 pin 的）/ `live_state`（本地 auth.json
  与已存账号的关系）是三个不同概念，本轮没有合并它们。

## 3. 数据库迁移（v17 → v18）

`SCHEMA_VERSION` 17 → **18**（`src-tauri/src/database/mod.rs:59`）。

- `schema.rs::migrate_v17_to_v18` 只调用 `create_official_account_tables`，建上述三表 + 一个索引；
  同时这三个 `CREATE TABLE IF NOT EXISTS` 也写进了 `create_tables_on_conn`，因此**新库**
  （以及测试用的 `Database::memory()`）不需要跑迁移也能拿到表。
- **纯 additive**：不 ALTER 任何既有表，不动既有行，因此对已有用户数据无损。
- 迁移在 `SAVEPOINT schema_migration` 内执行，失败整体回滚，`user_version` 不前进。
- 备份策略沿用了既有行为：`Database::init` 在 `version >= 17` 时只做一次
  `backup_database_file()`，**失败仅 warn 不中止**（v17 以下才强制备份）。v18 是纯建表，
  失败回滚即可，不存在丢数据路径，故未改动这个门槛。
- **降级风险（如实记录）**：应用降级回 v2.8 时，旧版本会读到 `user_version = 18 > 17`，
  按既有逻辑直接拒绝打开并提示「数据库版本过新…请升级应用」。这是既有策略，不是本轮新增的。
  需要降级时先备份 `chimera.db`，再由旧版本重建（标签/分组会留在库里但读不到）。

## 4. 对前端的 API 变更清单

### 4.1 兼容性总则

- **`list_official_accounts` 的返回类型没变**（仍是 `Vec<OfficialAccountDto>`），
  但每个元素**多了 9 个字段**：纯增字段，旧前端忽略即可，不会解析失败。
- 其余都是**新增命令**，不动旧命令的入参；唯一行为变化是
  `get_official_account_quota` 多了一个可选的 `refresh` 参数（见 4.4）。

### 4.2 `OfficialAccountDto` 新增字段（camelCase）

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `tags` | `string[]` | 标签，已去重保序（区分大小写） |
| `groupId` | `string \| null` | 分组 id |
| `groupName` | `string \| null` | 分组名（省一次 join，便于列表直接渲染） |
| `note` | `string \| null` | 备注 |
| `disabled` | `boolean` | 用户停用 |
| `disabledAt` | `number \| null` | 停用时刻 ms |
| `disabledReason` | `string \| null` | 停用原因 |
| `lastUsedAt` | `number \| null` | 最后使用 ms |
| `quota` | `OfficialQuotaDto \| null` | **缓存**的配额读数；`null` = 从未查过 |

既有 14 个字段（`key`、`accountId`、`displayName`、`email`、`planType`、`lineName`、
`capturedAt`、`isCurrent`、`isSelected`、`needsRelogin`、`unreadable`、`accessExpired`、
`providerId`、`liveState`）**语义与取值完全不变**。

> 注意：`list_official_accounts` 和 `query_official_accounts` **永远不会联网**。
> 列表里的 `quota` 只是「上次读到的值」，要新数据必须调 4.4 的刷新命令。

### 4.3 查询：`query_official_accounts`

```ts
invoke('query_official_accounts', { query?: OfficialAccountQuery }) => OfficialAccountPageDto
```

```ts
type OfficialAccountQuery = {
  search?: string;          // 大小写不敏感，匹配 displayName/email/accountId/note/groupName/planType/tags
  tags?: string[];          // 必须全部命中（AND）
  group?: string | null;    // 分组 id；"" 表示「未分组」
  filter?: 'all' | 'current' | 'selected' | 'needsRelogin' | 'accessExpired' | 'disabled' | 'unreadable';
  sort?: 'manual' | 'quota' | 'name' | 'lastUsed' | 'added';
  direction?: 'asc' | 'desc';
  page?: number;            // 1 起
  pageSize?: number;        // 默认 50，钳到 1..200
};

type OfficialAccountPageDto = {
  items: OfficialAccountDto[];
  total: number;            // 过滤后总数
  unfilteredTotal: number;  // 未过滤总数
  page: number;             // 越界时被钳回 1..totalPages
  pageSize: number;
  totalPages: number;
  tags: string[];           // 全量标签词表（已排序去重），供筛选工具栏
  groups: OfficialAccountGroupDto[]; // 全量分组（含 accountCount）
};
```

排序语义（**缺失值一律排最后**，与升/降序无关）：

| `sort` | 升序 | 降序 |
| --- | --- | --- |
| `manual` | 线路顺序，未绑线路的在后 | 整体反转 |
| `quota` | 用量少在前（`utilization` 最小） | 用量多在前 |
| `name` | A→Z（大小写不敏感） | Z→A |
| `lastUsed` / `added` | 旧在前 | 新在前 |

### 4.4 配额

```ts
invoke('get_official_account_quota', { key, refresh?: boolean }) => OfficialQuotaDto
```

- `refresh = false`（默认）：缓存还新鲜就直接返回缓存，**不联网**。
- `refresh = true`：用户点「刷新」时用；10 秒内重复点击会复用上一次结果（去抖）。
- 失败后 60 秒内不重试，直接返回上次结果（含错误信息）。
- 新鲜度窗口：成功读数 **5 分钟**（与 Claude 侧 `AUTO_INTERVAL_MS` 对齐）。
- 令牌过期时不再发请求：直接返回 `credentialMessage = "令牌已过期，切换后由 Codex 续期"`，
  `accessExpired = true`（沿用既有文案）。
- 返回值结构没变（`SubscriptionQuota` 拍平 + `accessExpired`）。

### 4.5 元数据写入

| 命令 | 入参 | 返回 |
| --- | --- | --- |
| `set_official_account_tags` | `{ key, tags: string[] }` | `string[]` 存下来的标签（已 trim/去重） |
| `set_official_account_group` | `{ key, group?: string \| null }` | `void`；`null`/`""` = 移出分组 |
| `set_official_account_note` | `{ key, note?: string \| null }` | `void`；空白 = 清空 |
| `set_official_account_disabled` | `{ key, disabled: boolean, reason?: string \| null }` | `void` |
| `mark_official_account_used` | `{ key }` | `void` |

校验规则（后端强制，前端应做同样提示）：

- 标签：单个 ≤24 字符、最多 12 个；trim、去空、去重（保留首次写法、区分大小写）；拒绝控制字符。
- 备注：≤1000 字符。
- 停用原因：≤200 字符。
- `group` 必须指向已存在的分组，否则 `InvalidInput("分组不存在或已被删除")`。
- `key` 必须是合法 account key，否则 `InvalidInput`（防止写垃圾行）。

`mark_official_account_used`：切换成功后调用，让「最后使用」立刻准确。
不调用也不会错——列表读取时会自动给 `isCurrent` 的账号打时间戳（5 分钟节流）。

### 4.6 批量删除

```ts
invoke('remove_official_accounts', { keys: string[] }) => {
  removed: string[];
  failed: { key: string; error: string }[];
}
```

- **非原子**：逐个账号走完整的「先解绑全部线路 pin、再删凭据」流程；成功的保持删除，失败的
  保留并带上原因。重试只需处理 `failed`。
- 重复的 key 会去重。
- 删成功的账号会一并清掉标签/分组归属/配额缓存；删失败的**不动**元数据（账号还在列表里）。
- 既有单条 `remove_official_account` 行为不变（只是现在也顺手清元数据）。

### 4.7 分组

| 命令 | 入参 | 返回 |
| --- | --- | --- |
| `list_official_account_groups` | — | `OfficialAccountGroupDto[]` |
| `create_official_account_group` | `{ name, color?: string \| null }` | `OfficialAccountGroupDto`（`accountCount: 0`） |
| `update_official_account_group` | `{ id, name, color?: string \| null, sortIndex?: number \| null }` | `void` |
| `delete_official_account_group` | `{ id }` | `number`：被移出该分组的账号数 |
| `reorder_official_account_groups` | `{ ids: string[] }` | `void`；数组顺序即新顺序 |

```ts
type OfficialAccountGroupDto = {
  id: string;
  name: string;
  color: string | null;
  sortIndex: number;
  accountCount: number;
};
```

- `color` 必须是 `#RGB`/`#RRGGBB`/`#RRGGBBAA`（大小写不敏感，存小写），否则 `InvalidInput`。
  传 `null` 表示清空颜色。
- 分组名 ≤40 字符且非空。
- `delete` 在**一个事务**里先清成员 `group_id` 再删分组，不会留下悬空引用。
- 若分组已不存在，`update` / `delete` 返回 `InvalidInput("分组不存在或已被删除")`。

## 5. 前端落地清单（下一阶段）

1. `types.ts` 给 `OfficialAccount` 补 9 个字段（全部可选/可空，避免破坏现有渲染）。
2. 账号页改用 `query_official_accounts`（分页 + 搜索 + 筛选 + 排序），
   `list_official_accounts` 仅保留给「确实要全量」的场景。
3. 工具栏：搜索框（防抖 250ms）、标签多选（来自 `tags`）、分组下拉（`groups` +
   「未分组」= `""`）、6 个 filter、5 种 sort。
4. 行内展示配额徽章用 `quota`（缓存值），**不要**在渲染时调 `get_official_account_quota`；
   刷新按钮传 `refresh: true`。
5. 多选 + 批量删除接 `remove_official_accounts`，失败项逐条提示。
6. 标签编辑、分组管理（新建/重命名/改色/拖拽排序）、备注、停用开关分别接 4.5 / 4.7。
7. 停用账号：列表里置灰，不提供「切换」入口（后端只是标签，是否禁用切换是前端策略）。

## 6. 已知边界 / 遗留

- 2.9.0 前端已接：`refresh: true`（手动刷新与定时刷新）、标签 / 备注 / 分组（新建、删除）/ 停用的编辑、
  批量删除。未接：分组重命名、改色、排序，以及 `query_official_accounts` 分页查询
  （页面仍然一次读全量、本地筛选）和 `mark_official_account_used`。
- 停用只在官方账号页生效（不提供切换、不读额度、正在使用的账号不能停用）；线路页、命令面板和托盘
  仍然可以切到已停用账号的线路。

- `last_used_at` 依赖「`isCurrent` 的账号被读到」这一事件，因此只在打开账号页（或调
  `mark_official_account_used`）时刷新，最多晚 5 分钟。
- 账号页展示的 `lastUsedAt` 是**写入前**读到的值，可能比真实时刻旧最多一个节流窗口。
- 分组计数来自当前列表里的行，不来自 `official_account_meta`：元数据行可能残留在
  「slot 已被外部删除」的 key 上（下次删除同一账号时会清掉）。
- 上游 cockpit-tools 的 `validation_url`（配额报错后一键重新授权）本轮**未做**；
  报错只落 `error` 文案。
- 未做：回收站/软删除、账号级出口代理、自动切号、配额预警通知（这些属于后续迭代）。
- 本轮未写前端任何代码，也未改动 `src/` 下任何文件。
