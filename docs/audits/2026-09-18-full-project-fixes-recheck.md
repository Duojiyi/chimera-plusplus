## 交叉复审过程

修复与审查由不同审阅者承担，最终差量再次交回发现问题的审阅者确认。属于独立代码审阅和交叉复核，不声称满足实验意义上的严格“双盲”。

复审中新发现并已闭合：

1. 更新页保存尚未完成时离开再返回，可能读取中间状态。提升共享保存队列并补成功/失败两类重挂载行为测试；作者确认两条用例修复前失败、修复后通过。
2. OpenCode 合法消息 ID 仍可能引用其他会话 part。补全文件名和会话归属一致性验证，任何写入前完成预检。
3. 无关损坏元数据导致所有会话无法删除。按目标文件名和发现规则识别候选，跳过不可识别的无关文件，目标损坏仍拒绝。
4. 云下载仍使用孤立 AppState。统一共享状态，并在下载替换及后置同步期间持有正确的保护锁。
5. 云端 proxy_config 不属于本地保留表，运行标记原本可能先提交后告警。改为恢复本地保留表后校验最终暂存库，在安全备份和提交前拒绝。
6. 底层累加模式 provider/Skill 同步吞错，上层仍可能假成功。改为继续尝试其他项目、最终汇总返回失败，补聚合及两个非法 provider 的 Rust 回归源码。
7. WebDAV/S3 页面忽略后端 warning。两种下载路径均显示部分成功警告及详情，不显示完整成功提示，同时刷新查询。

## 使用约束与未执行验证

- 按用户约束，未运行 cargo build/test/check/clippy、tauri build/dev，也未生成新的桌面可执行文件。新增 Rust 测试仅完成源码和格式核验，不能报告为执行通过。
- 本地或云端恢复要求本机代理已停止、接管已关闭；最终快照仍含运行/接管标记时，提交前拒绝。运行中源设备上传的云快照可能因此被拒绝，需要先停止源设备代理和接管并重新上传。暂不支持代理运行中的热恢复。
- 云下载网络阶段也持有相关共享锁，期间线路切换和代理操作可能等待，优先保证恢复一致性。
- SQLite 和文件系统不具备跨资源原子事务；删除中途失败可能已移除部分文件，但不会报告完整成功。路径式预检不能原子防御外部进程同时替换祖先目录。
- 源码契约测试检查接线和顺序，不等于 Rust 并发测试；没有在真实用户数据上执行删除、恢复、安装或终端命令。
- 尚未验证全部历史会话格式、真实 Windows/macOS/Linux 运行、真实升级回滚和网络/磁盘故障。结论是本轮已确认问题闭合，不是对全项目“绝对无问题”的保证。
