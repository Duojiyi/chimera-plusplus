### §0.1 用户锁定决策
1. Pi = cc-switch 的 Pi。
2. 多工具 = **轻量**:每工具只做供应商配置 + 模型 + 切换(或条目增删);非 Codex 工具不做运行时/换肤/独立会话与用量。
3. `PRODUCT.md` 从 Codex-only 改为多工具。
4. 代码移植改写、能复用优先复用,保留 MIT 归属与 THIRD_PARTY_NOTICES。
5. 提示词功能:机制完整保留 + 用户自由选择 + 文档说明。
6. 历史热修并入 v2.8.0;UI 先设计后落代码。
7. 许可证保持 MIT;不做云同步;多官方账号做;能吸纳的都吸纳;其余决策由计划作者按最佳实践定(§1.5)。

### §0.2 边界(硬约束)
- **提示词越狱内容**:管理机制 100% 移植;安装包只内置 6 个正当模板(`software-development-{code-review,debugging,maintainer}`、`writing-{clarity-editor,structured-draft,technical-docs}`),以 **sha256 允许清单**校验"恰好这 6 个";不预置 Codex-X 编入其二进制的 5 个越狱模板及其代码层耦合(见 M4 排除清单);不设任何含越狱内容的默认同步源;同步默认关闭,用户可自加任意源。文档与 UI 写明"内容中立的管理器,用户对自己导入和启用的内容负责"。
- **上游排除**:按真实模块名排除远控/注入/浏览器脚本/市场/广告/分享/移动中继等子系统(§3)。Codex-X 的 `remote.rs` 只是 HTTP 抓取工具,不移植,由我方 HTTP 客户端承接需求。
- **CodexPlusPlus 净室协议(D1、MH-11⑧)**:实现会话只接收行为规格与我方代码,不接收 CPP 源码、文件名或函数名;CPP 相关批次开工期间,对本机 CPP 克隆与运行时工作树设置代理读取禁止规则(或移出可达路径);保留会话日志;CI 对 `cleanroom:` 标记的 PR 做相似度扫描。CPP 相关批次的实现会话只接收该批的行为规格摘录,**不接收本计划全文**(§3 含 CPP 文件名,R3A-N14);三 crate 先经干净导出并入主仓(保留 AGPL 声明),重写在主仓内进行(MH-11 细则 ⑪)。
- **Codex-X 归属**:THIRD_PARTY_NOTICES 新增 Codex-X 条目(源 `yynxxxxx/Codex-X`,参考提交 `73f0c4ca` = v0.3.21,`Copyright (c) 2026 yynxxxxx`,MIT 全文,列吸收领域);含实质 Codex-X 代码的文件加来源文件头;内置模板在 `resources/prompts/` 旁放归属清单,不改模板正文;NOTICES 不写出被排除的越狱文件名。
- **构建边界**:本地只编辑与静态检查(typecheck、`cargo fmt --check`、前端聚焦测试);其余交 CI。
