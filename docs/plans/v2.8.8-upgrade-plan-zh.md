## 1. 本版主题

1. **数据安全与可靠性**：修掉会损坏配置、重启电脑、静默丢数据的问题（第 2 节）。
2. **依赖与引擎回到上游**：tauri 2.12 整体升级、撤掉自维护的 Codex 引擎补丁分支（第 3 节）。
3. **协议转换与工具管理的正确性修复**（第 4 节）。
4. 适量处理积压的界面打磨（第 6 节），大功能继续暂缓（第 7 节）。

## 4. P2（建议本版做）

**配置与文件安全**
- C1 ✔ **Windows 替换文件不重试**：杀毒软件或 Codex 短暂占用目标文件时，保存或切换线路直接失败。在 `config.rs` 的 `MoveFileExW` 处加有限重试（上游最多 6 次）。CodexPlusPlus `7fe01311`，S。
- C2 ✔ **JSON 配置带 UTF-8 BOM 读不出**：`read_json_file`（`config.rs:237`）不去 BOM，有 75 处调用；用记事本改过的文件会读失败。2.8.7 只修了 `settings.json`。CodexPlusPlus `d0fcf52c`，S。
- C3 **历史归桶遇到被占用的会话文件时整轮失败**：Windows 上 Codex 正在写的会话文件被锁，应改为"延期"而不是中止；注意不要误吞拒绝符号链接时的同类错误。CodexPlusPlus `f2d4246e` 等，S；Windows 实测待确认。
- C4 **Gemini `.env` 的 `export KEY=value` 行被丢掉**，切换线路后重写文件时丢键（`gemini_config.rs` 的 `parse_env_file`）。CC Switch，S。
- C5 **oh-my-pi `models.yml` 被整体重写**，注释丢失、锚点被展开（`commands/omp.rs:110,249`）。先做"检测到注释或锚点就提示确认"。CC Switch，S。
- C6 **TOML 智能引号规范化会改写合法字符串内容**（`textNormalization.ts` 全局替换，约 25 处调用，含 Codex 配置编辑器和 MCP 表单）。CC Switch `1f1becfb`，S。

**协议转换与代理**
- D1 ✔ **本机推理地址走了全局代理**：线路指向 localhost、127.x、::1（Ollama、LM Studio、vLLM）时会失败。给全局代理加本机地址例外。CodexPlusPlus `78162cbc`。这一项会关闭 2.8.7 待办里的同名条目，S。
- D2 **上游地址指回我们自己的代理时没有拦截**，会形成循环（`forwarder.rs:1556-1575`）。CC Switch `cd9c7210`，S–M。
- D3 **Gemini 不接受 `enum:[true,false]` 或数字枚举的工具定义**（Codex→Chat，`transform_codex_chat.rs` 约 346 行）。CodexPlusPlus `57205ba2`、`c0514a22`，S。
- D4 **Claude Code 走 Responses 上游时出现 `redacted_thinking` 错误**：应输出带签名的空 thinking 块，并补收迟到的摘要（`reasoning_bridge.rs`、`streaming_responses.rs`）。CC Switch `7ecce7c7`，M。
- D5 **原生 Responses 中转拒收 `image_generation` 工具**：Chat 转换路径已处理，直连 Responses 没有；做成自动剥离后重试一次。CodexPlusPlus，M。
- D6 **Codex 会话头的 `session-id`、`thread-id` 别名**（`proxy/session.rs`）。CC Switch `2e1e2979`，S；需先抓包确认当前 Codex 发的是哪个。

**工具管理与界面**
- E1 ✔ **npm 12 下安装工具跳过 postinstall 却仍返回成功**：OpenCode 装成占位二进制，Grok Build 升级后仍是旧版。安装命令补 `--ignore-scripts=false --include=optional`（`commands/misc.rs`）。CC Switch，S。
- E2 **Windows「打开终端」一直转圈直到终端关闭**：`run_windows_start_command` 用了 `.output()` 等待子进程。CC Switch `6226f5c4`，S。
- E3 **Claude Desktop 的 `inferenceModels` 按字母排序，导致 Fable 成了默认模型**（`claude_desktop_config.rs:681,740`）。改为 Sonnet、Opus、Fable、Haiku 顺序，与待办「Claude 5.5 模型 ID」一起做。CC Switch，S。
- E4 **Claude、Gemini、Grok 的会话删除不可恢复**（只有 Codex 在 2.8.7 加了备份）。CodexPlusPlus `4a5ad45d`，M。这一项扩大并提升了待办「会话删除撤销」，建议把恢复入口和备份清理入口一起做（CodexPlusPlus 1.11 有最小设计可参考）。
- E5 **模型获取地址候选**：`…/v1beta/openai` 这类地址拼出 `…/v1beta/openai/v1/models` 会 404（`services/model_fetch.rs:1620-1724`）。CodexPlusPlus，S。可顺带关闭待办「Gemini 获取模型」中 OpenAI 兼容的那一半。
- E6 **Codex 远程压缩的用量被记为 0**：`session_usage_codex.rs` 不读 `token_usage_record`。CC Switch `8cfe5644`，S–M；先用真实会话确认记录格式。
- E7 **「替我审批」用的 `codex-auto-review` 模型**：我们完全不处理，按线路配置审批模型。CodexPlusPlus `a95c683b`、`062a6837`，M；先抓一次真实请求确认。

## 7. 暂缓与不做

- **暂缓（大功能或缺证据）**：
  - 托盘快捷面板：上游这几版又改了约 660 行，主要是 DPI 和多显示器问题，成本更高了；可先在原生菜单里补「当前线路 + 余额」摘要。
  - 一条线路多个命名 Key、OpenCode「设为默认模型」（我们的 `opencode_config.rs` 整文件重写会丢注释，要先解决这个）、Claude Desktop 设备级模式、工具卸载。
  - Responses 的 Code Mode `exec` 适配、压缩会话归桶改写（上游这期间都没碰）。
  - CodexPlusPlus 的「请求避震」整套重试、提示词前缀稳定器、批量归档（上游只改 DB 标记不移动文件，与 Codex 自身行为不符，不要照搬）。
  - CC Switch 新增的 Kimi Code、Antigravity 等托管工具：属于产品范围决定，不放进 2.8.8。
- **不做**：
  - CodexPlusPlus 2.0 的「网关模式」（多智能体共享供应商池、按模型名路由）：与我们「每个工具一条线路」的设计不同，网关层的修复基本不适用。
  - 所有向 Codex 渲染进程注入脚本或修补客户端的功能（Computer Use 增强、界面注入等）；Copilot 原生路由。

## 8. 执行建议

1. **先解封 CI**：单独升 Vitest 修复版，合并 #111–#113。
2. **第一批（数据安全）**：A1、A2、C1、C2、C4、C6、D1、E1。都很小，能最快消除风险。
3. **第二批**：B1 tauri 2.12 整体升级与 B2 引擎回到上游，各自独立分支、独立 CI。
4. **第三批**：第 4 节其余 P2、第 6 节、选定的第 5 节项目。
5. **收尾**：两路独立双盲审计（各自覆盖全量差异，读代码并在 QA 界面渲染截图）→ 修复 → 发布。

**发布流程沿用 2.8.7 的经验**：
- CI 用 `watch-runs.sh` 盯：任何一个任务失败立即报告。
- 发版当天先跑一遍 `cargo audit` 和 `pnpm audit`，提前发现当天新出的安全公告。
- 改了引擎版本后确认引擎工作区的 `--locked` 校验通过；便携版 CI 已覆盖这一点。
