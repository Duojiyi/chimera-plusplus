## Corrections CI caught (kept visible rather than silently squashed)

- **MH-8a deep-link fix, round 1 was wrong.** My first attempt left
  `meta.api_format`/`meta.api_key_field` fully unset after removing the probe,
  reasoning that this "defers to the same model-family runtime default the
  manual path uses." That's true for the *manual* path only because it
  explicitly computes and persists the model-family default into
  `meta.apiFormat` at save time — it doesn't actually rely on the backend's
  fallback chain either. I'd missed that `build_codex_settings` (the deep-link
  config builder) always writes a Codex-side `wire_api = "responses"`
  declaration into the generated `config.toml`, regardless of the upstream's
  real protocol, and that declaration wins in `codex_api_format_for_model`'s
  fallback chain *ahead of* the model-family default — so leaving the field
  unset silently resolved every deep-linked import to Native Responses.
  CI's real test run (not something source review caught) failed 3 tests on
  this exact gap. Fix: explicitly compute and persist `meta.api_format` from
  the model name at import time, mirroring what the manual path actually
  does rather than what I assumed it relied on. Exposed
  `codex_model_default_api_format` as `pub(crate)` for this.
- **Lesson for the rest of this effort**: "the manual path doesn't need X, so
  neither does this" is only safe once I've checked *why* the manual path
  doesn't need it, not just that it doesn't. Source review found the right
  general direction here but got a load-bearing detail wrong; the regression
  tests (which I'd also updated, so they didn't independently catch it either
  — they asserted the *new* intended behavior, which was itself built on the
  same wrong assumption) only became real signal once CI actually ran them.
