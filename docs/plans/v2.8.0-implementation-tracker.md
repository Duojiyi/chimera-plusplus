# v2.8.0 Implementation Tracker

Живой checklist against `docs/plans/v2.8.0-upgrade-plan-zh.md` (v1.0). Backend/non-UI
scope only, per the maintainer's 2026-09-27 instruction: implement everything except
the frontend UI (M5a/M5b), stop for a double-blind audit once done, then hand off for
UI design.

Status values: `TODO` / `IN PROGRESS` / `DONE` / `BLOCKED` (needs the user) /
`DEFERRED` (structurally gated — G2a, real machine, GitHub auth, etc.) /
`ALREADY FIXED` (plan cited a defect that turned out to already be resolved —
verified against current code, not assumed).

Working branch: `v2.8.0/backend` (off `origin/main` @ `f4c5a5c0`, backend content
identical to `v2.7.10`). Rust changes are not compiled locally per this repo's
`AGENTS.md`; every row's "Verification" column states how it was actually checked
(source review / local script run / regression test added, pending CI) rather than
claiming a build passed. `cargo fmt`/`cargo fmt --check` (no compilation, explicitly
allowed) runs after every batch of Rust edits before committing — CI's format-check
step gates clippy and `cargo test` behind it, so a formatting slip otherwise burns a
full CI round for zero real signal. Learned this the hard way on PR #110's first
round: 3-platform failure that turned out to be pure formatting, clippy/tests never
ran.

PR #110 (draft) is kept open and pushed to as work continues — the actual compile/
test/clippy oracle, since local `cargo build/test/check/clippy` aren't run.

## How this will be audited

- Checkpoint double-blind audits after each phase group below (not just at the very
  end) — two independent review passes per checkpoint, same methodology as the v1.0
  planning audits (frozen snapshot, cross-confirmation, findings ranked by severity).
- A final double-blind audit round covers the whole backend diff before declaring
  this tracker done and handing off for UI design.
- CI (pushed branch / PR) is the actual Rust build+test oracle; audits are source-level
  review on top of that, not a replacement for it.

## Corrections CI caught (kept visible rather than silently squashed)

- **MH-8a deep-link fix, round 1 was wrong.** My first attempt left
  `meta.api_format`/`meta.api_key_field` fully unset after removing the probe,
  reasoning that this "defers to the same model-family runtime default the
  manual path uses." That's true for the *manual* path only because it
  explicitly computes and persists the model-family default into
  `meta.apiFormat` at save time — it doesn't actually rely on the backend's
  fallback chain either. I'd missed that `build_codex_settings` (the deep-link
  config builder) always writes a Codex-side `wire_api = "responses"`
  declaration into the generated `config.toml`, regardless of the upstream's
  real protocol, and that declaration wins in `codex_api_format_for_model`'s
  fallback chain *ahead of* the model-family default — so leaving the field
  unset silently resolved every deep-linked import to Native Responses.
  CI's real test run (not something source review caught) failed 3 tests on
  this exact gap. Fix: explicitly compute and persist `meta.api_format` from
  the model name at import time, mirroring what the manual path actually
  does rather than what I assumed it relied on. Exposed
  `codex_model_default_api_format` as `pub(crate)` for this.
- **Lesson for the rest of this effort**: "the manual path doesn't need X, so
  neither does this" is only safe once I've checked *why* the manual path
  doesn't need it, not just that it doesn't. Source review found the right
  general direction here but got a load-bearing detail wrong; the regression
  tests (which I'd also updated, so they didn't independently catch it either
  — they asserted the *new* intended behavior, which was itself built on the
  same wrong assumption) only became real signal once CI actually ran them.
