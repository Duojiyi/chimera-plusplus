## 1. 会话与历史

- [ ] **P2 · 压缩会话归桶时 DB 与文件不一致**（Codex-X f6feba9）：历史归桶迁移只改写明文 `.jsonl`，`.jsonl.zst` 被跳过，但 state DB 里同一会话的 `model_provider` 照样被改。后果取决于 Codex 恢复/重建索引时以哪边为准，**未验证**。验证：在一份含压缩会话的 `.codex` 副本上归桶，再用 Codex 恢复该会话。若会回弹：先做"把来源桶中的压缩会话列入 deferred"（小），再考虑"解码 → 改写 session_meta → 重压 → 原子替换"（中，需复用活跃文件跳过、前后复核、备份）。暂缓理由：改写用户压缩历史风险大于未经证实的收益。
- [ ] **P3 · 会话列表缓存**（CodexPlusPlus 1d8f54d）：`list_sessions` 每次都全量扫描并解析所有 rollout。先用约 5000 个 rollout 计时，再决定是否加"目录指纹 + 30 秒"缓存。
- [ ] **P3 · 会话删除撤销**：2.8.7 已在删除前备份对话文件（数据目录下 `backups/codex-session-delete/`，含 manifest；保留最近 20 份，7 天内的不清理），但没有恢复入口和备份清理入口。
- [ ] **P3 · 删除与迁移互斥**：会话删除路径未持有历史迁移锁，窗口很小。

## 3.1 2.8.7 双盲审计留下的 P3

- [ ] **会话导出后标题被保存路径挤压**（`SessionExportButton.tsx` 的 `session-export-location`）：路径改到标题下一行或折叠成「已保存 ✓」+ 提示。
- [ ] **「管理线路」对话框没有遮罩**；命令面板里双字头像（如「自建」「智谱」）比单字母宽，文字错位约 4px。
- [ ] **开关样式不统一**：提示词页是玻璃蓝 Radix Switch，Skills/MCP、设置、Pi 仍是近黑色自绘开关。
- [ ] **改过 Codex 配置目录后**，旧的绝对 `model_catalog_json` 指针被当成自定义目录，每次切换都报冲突（`codex_config.rs` 所有权判断）。可把「同名且位于任一已知 Codex 配置目录」的指针视为自有并迁移。
- [ ] **无法校验内容的本地 Skill 目录被静默跳过**：只写日志，界面不提示（`skill.rs` `scan_unmanaged_scoped`）。
- [ ] **引擎补丁 `codex/zip-9-engine` 的 `app_version.rs`** 用 `.ok()?`，一个条目名不合法就读不出已安装 Codex 版本；上游循环其余处用 `continue`。官方 MSIX 不会出现，随引擎下次升级一起改。
- [ ] **bzip2 / zstd 压缩的 Skill ZIP 现在会被拒绝**（2.8.7 只启用 deflate 与 deflate64 解码）。若有用户反馈再按需开启。

## 4. 不做（记录在案）

- 「Codex 简体中文」、原生 Fast 解锁、官方额度解锁、用量状态栏、模型选择器分组：都需要向 Codex 渲染进程注入脚本或修补客户端，越过产品边界。
- 外部 Agent 委派（CodexPlusPlus 3c225ca 等）：新的产品面（本地 MCP 服务、跨 CLI 凭据复用），需单独设计评审。
- 聚合模型、Windows 多开、Windows Store 版 Codex、macOS LaunchServices 重启：我方没有对应模块或平台。
- 预设、价格表、赞助商、土耳其语。

## 5. 开发与发布注意

- **Codex 引擎补丁分支**：`codex-win-engine` / `codex-theme-engine` 固定在本仓库 `codex/zip-9-engine` 分支（上游 Codex App Manager v0.5.16 = 31bd3f23 + zip 9 补丁）。上游发布 zip 9 版本后，改回直接引用上游并删除该分支；改动时同步 `src-tauri/Cargo.toml` 的 `[patch]`、`.github/workflows/release.yml` 的溯源仓库和 `scripts/release-workflow-guards.test.mjs`。
- **tauri-plugin-updater 不启用 `zip` 特性**：我们的更新包是 .msi / .AppImage / macOS .tar.gz（后者不受该特性控制）。若改为 v1 兼容的 zip 更新包，必须重新启用并解决 zip 4 的安全公告。
- **settings.json 备份失败会拒绝保存**：日志关键字「备份设置文件失败」。
