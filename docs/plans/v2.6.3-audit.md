## 二、修复 1：Responses 条目 ID 前缀漂移（fc_ / ctc_）

外部反馈（GitHub）：BigPizzaV3/CodexPlusPlus#1894、#1929；openai/codex#40039；
Wei-Shaw/sub2api#6071 —— 同一错误文本
`Invalid 'input[N].id': 'fc_…' Expected an ID that begins with 'ctc'`。

根因链：Chat→Responses 转换时工具类型查表失败 → `custom_tool_call` 被误加 `fc_` 前缀 →
Codex 原样落盘 → 后续每轮重放被上游 400 拒绝，整个会话被“污染”。

变更：
- 新增 `src-tauri/src/proxy/providers/codex_id_normalize.rs`（纯函数归一化器）。
- `src-tauri/src/proxy/handlers.rs` 两个入口（`/responses`、`/responses/compact`）解析后
  调用归一化并回写 `body_bytes`（保证 Chat 自动回退重试重新解析时也读到修复后的 body）。

边界：仅修复确定损坏的条目；不改 `call_id`；无 id 不新增；未知类型不触碰。

## 三、修复 2：历史版本目录一直“正在加载”

根因（本机实测复现）：`list_codex_runtime_releases` 走外部依赖进程外 `curl`，
其 `run_capturing` 先等进程退出再读 stdout；Windows 匿名管道缓冲区约 4KB，而 releases
目录实测 427KB → curl 写满管道背压、永不退出，直到 75s 兜底超时。期间前端停留在“正在加载”。

变更：
- 新增 `fetch_mirror_text`（应用内 reqwest，跟随全局代理、20s 超时、8MB 上限、标准 UA、
  错误体截断附回）。
- `list_codex_runtime_releases` / `plan_codex_runtime_release` 由 `spawn_blocking` 改为 async/await。
