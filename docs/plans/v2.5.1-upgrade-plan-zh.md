### 0.2 实施前置条件

1. 实施分支从 `origin/main`（≥ `2d870fdb`）创建；沿用 CI-only 构建边界（本机只编辑与静态检查，验证全部在 GitHub Actions）。
2. **V1 先行**：动工引擎升级（D1）前先完成 v2.4.6 → v2.5.0 实机升级验收——若 v2.5.0 存在需要热修的缺陷，v2.5.1 必须先降级为纯修复补丁，本计划顺延。
3. M1 漂移扫描若发现三上游有新发布，先按 v2.5.0 的审计流程增量更新同步矩阵，再冻结本周期范围。
4. 每周期一次的例行核对：`v2-task-10-owned-mirror` 分支（chimera-runtime workspace）与 `src-tauri` 的引擎 rev 必须始终一致，升级必须双侧联动。

## 1. 版本定位与决策门

**v2.5.1 主线（承诺交付）**：D1 引擎升级 + 主题回归、D2 OMO 统一写入、V1/V2 验证收口。这些是既有能力的升级与补全，符合 patch 定位。

**决策门（评估后决定是否纳入本周期）**：

- **D3 macOS 运行时管理**：新平台功能。纳入的前提是：`codex-mac-engine` 在固定 rev 下 API 稳定、macOS CI 能承载 `.app` 原子替换的集成测试、且有真实 macOS 设备完成人工验收。满足则随本周期交付并将发布号升为 **2.6.0**；不满足则继续挂账并在同步矩阵记录阻塞原因。
- **D4 面板挂载 + 搜索/批量**：产品边界决策。两个出口：(a) 把 MCP/Skills/Prompts 面板正式挂载进 `ChimeraApp` 导航（新增产品面），随后实现搜索与批量启停——交付则升 **2.6.0**；(b) 判定这些面板不属于 Chimera++ 产品边界，从源码树移除组件与测试（消除死代码），在同步矩阵把 G5 关闭为 `not-applicable`。**两个出口都比现状（无限期挂账的死代码）好，本周期必须二选一。**

决策门在 M1 结束时定案，定案结论写入本文件 §0.1 表格与同步矩阵，不允许"到发布前再说"。

## 2. 分阶段实施（M1–M6）

### M1：漂移扫描、决策门定案与依赖升级分支（前置）

- 三上游漂移扫描（对照 2026-08-12 audit：v3.19.2 / v1.2.47 / v0.5.2），增量更新同步矩阵。
- V1 实机升级验收执行并记录（阻塞后续里程碑）。
- D3/D4 决策门定案（评估记录写入同步矩阵）。
- 创建引擎升级分支：`src-tauri/Cargo.toml` 与 `v2-task-10-owned-mirror` workspace 同步指向 `d29fda32`，列出编译破坏面（已知：`lib.rs` msix 导出重组、`MsixIdentity.resource_id` 新字段、`read_codex_app_version_from_msix` 新 API）。

**验收**：漂移结论、V1 验收记录、决策门结论、可编译的依赖升级分支。

### M2：引擎升级落地 + 主题回归（D1）

- 处理 `89b542b9` → `d29fda32` 的 API 变化；采纳上游加固：ASAR 读取上限（`MAX_ASAR_PACKAGE_OFFSET_BYTES`/`MAX_PACKAGE_JSON_BYTES`）、MSIX publisher-ID/`resource_id` 校验；离线导入路径改用引擎内置上限后，评估应用层前置校验哪些可以退役（保留不冲突者）。
- 主题引擎 4 项行为变更回归：Codex 26.727 主界面适配、composer scroll ownership、composer overflow cache、CSP-safe motion intros——在装有新版 Codex 的 Windows 实机验证主题应用/还原不破坏输入区。
- v2.5.0 的安装事务日志、历史版本、离线导入在新引擎下全量回归（`PortableBoundary` 语义不得漂移）。

**验收**：三平台 CI 全绿；主题应用/还原实机回归通过；安装链路（在线/历史/离线/回滚/事务日志）行为与 v2.5.0 一致。

### M3：OMO 统一配置写入（D2）

- 移植上游 round-trip JSON5 编辑基础设施（`rt_from_str`、`merge_rt_value`、`append_object_pair`、`object_layout`、`remove_object_pair_at` 及 `json5` 解析），保持注释/缩进/行尾风格不被破坏。
- 实现 `[opencode]` 分区写入与删除：重复分区检测、磁盘内容变化检测（保存前比对原文）、写后重解析校验（拒绝写出不可解析文件）、`omo_write_lock` 串行化。
- 移除 v2.5.0 的"检测到统一配置即拒绝写入"守卫，替换为真实写入；`delete_config_file` 在统一布局下只移除 `[opencode]` 分区、不删除用户的 `omo.jsonc`。
- 写入失败回滚沿用现有快照/恢复模式。

**验收**：对带注释/尾逗号/CRLF 的真实样本执行"读取→修改→写回"后，非 `[opencode]` 内容逐字节不变；重复分区/非对象分区/磁盘并发修改均显式失败不落盘。

### M4：macOS 运行时管理（D3，决策门通过才实施）

- 引入 `codex-mac-engine`（与 win-engine 同 rev 固定），实现检测/安装/更新/原子替换/健康检查/回滚。
- `.dmg`/`.zip` 离线导入：安装前完成大小上限 → SHA-256 → 签名/公证校验 → 身份 → 架构 → 版本。
- 解除相关命令的 `require_windows()`，安装事务日志与恢复横幅复用 v2.5.0 基础设施。
- macOS CI 集成测试 + 真实设备人工验收。

**验收**：macOS 安装/升级/回滚/离线导入全链路可用；中断恢复语义与 Windows 一致；Windows 行为零回归。

### M5：面板挂载 + 搜索/批量启停（D4，按决策门出口执行）

出口 (a) 挂载并交付：面板懒加载挂进 `ChimeraApp` 导航 → 三面板统一搜索（复用 SkillsPage 客户端过滤范式）→ MCP/Skills 按应用批量启停（串行、失败继续、结果汇总；后端批量命令合并文件同步开销）→ Prompts 按语义只做批量禁用/删除。
出口 (b) 移除：删除三面板组件、`AuthCenterPanel`/`SettingsPage` 死代码与关联测试，同步矩阵关闭 G5。

**验收**：出口 (a)——搜索三面板行为一致、批量操作有成功/失败明细、大列表不卡顿；出口 (b)——全仓无未挂载面板残留，`pnpm typecheck` 与全部测试通过。

### M6：回归、candidate 与发布

- 新增/更新测试：引擎升级 API 面（identity/resource_id/ASAR 上限）、OMO round-trip（注释/格式保持、并发修改拒绝、分区删除）、（若 M4）macOS 安装矩阵、（若 M5a）Bulk UI（搜索/批量/部分失败/取消/i18n key）。
- 发布链沿用 v2.5.0：分支 CI → PR 必需检查 → candidate（`--expect` 版本号）→ main CI 绿 → tag → release 门禁（tag-main CI 绑定、资产签名、`latest.json` 精确绑定）。
- 发布号定案：仅 D1+D2 → `v2.5.1`；含 D3 或 D5a → `v2.6.0`（CHANGELOG 与 tag 一致）。

## 3. 设计约束

1. 沿用 v2.5.0 全部既有约束：DB 唯一事实源、未知字段保留、迁移可重入、写前备份、依赖升级分批、补偿事务模式。
2. **引擎升级不改语义**：v2.5.0 的安装确认对象、事务日志、目标锁定语义在新 rev 下必须逐项回归，不允许"顺手"重构安装链路。
3. **OMO 写入宁可失败不可破坏**：任何 round-trip 不确定性（解析歧义、并发修改、重复键）都显式报错保留原文件；用户手写注释与格式是数据，不是噪音。
4. **macOS 不复制 Windows 语义**：MSIX/portable 概念不外推；`.app` 原子替换按平台惯例实现；Linux 继续保持现有包管理路径不变。

## 4. 测试与发布门禁

- 单元/集成：引擎 API 差异回归、OMO round-trip 样本集（含 CRLF/注释/尾逗号/Unicode）、安装链路全量回归、（视决策门）macOS 矩阵与 Bulk UI。
- 跨平台：Windows x64/ARM64、macOS Universal、Linux x86_64；主题回归需 Windows 实机 + 新版 Codex。
- 降级与回滚：新增字段只做加法；v2.5.0 可读取 v2.5.1/v2.6.0 配置库；OMO 写入前快照可手动还原；引擎升级独立提交、可单独 revert。
- 发布门禁与 v2.5.0 相同（六条），外加：V1 验收记录在案、决策门结论已写入文档。

## 5. 风险与决策记录

| 风险 / 决策 | 对策 |
| --- | --- |
| 引擎升级带入主题行为回归 | M2 实机回归清单前置；主题引擎问题可单独 revert rev（升级提交独立） |
| round-trip 编辑器移植破坏用户配置 | 写后重解析 + 原文比对 + 快照回滚；样本集覆盖真实格式变体；宁可失败不落盘 |
