## 0. 执行门禁

### 0.1 状态标记与优先级

- `[ ]` 未开始、`[-]` 进行中、`[x]` 完成、`[!]` 受阻
- `P0`：必须 v2.5.0 完成；`P1`：应随 v2.5.0 完成；`P2`：单独立项，不在本版主线
- 每项完成必须同时满足：代码完成、自动测试通过、GitHub Actions 证据可追溯、验收标准通过
- 禁止用「提交的 CI 成功」冒充完成，也禁止只证明文件存在而不验证 Codex 桌面实际行为

### 0.2 当前已确认的基线（2026-08-12）

- **上游计划中多数 P0 已在 v2.4.x 落地**（用量去重重建、日志/代理安全边界、工具缺函数名处理，v2.4.5 起还有按模型协议探测路由），本版不重复实现，只补回归测试。
- 本版主攻 8 项真实缺口：G1 系统证书链、G2 安装事务持久化、G3 离线安装/历史版本/macOS、G4 per-model 上游路由、G5 面板搜索+批量、G6 逐账号用量、G7 导入批处理、G8 OMO/Hermes 路径。缺口定义与现状证据见升级计划 §0.2。
- **审计基准**：§0.2 结论最初基于本地 `main`（`79c55545`，2.4.2 代码），已按 `origin/main`（`f44b103e`，v2.4.6）复核修正；本地 `main` 落后远端 12 个提交，实施前必须先同步（TASK-000）。

### 0.3 构建与测试边界

- 本机只允许：阅读/编辑代码、静态检索、`git diff`、`git status`、提交与推送。
- 本机禁止：`pnpm build`、`pnpm test:unit`、`cargo build/test/clippy`、`pnpm tauri build` 及任何安装包构建。
- 类型检查、单元测试、Rust 检查、跨平台构建、签名、打包与发布全部由 GitHub Actions 完成（沿用 v2.1.0 边界）。
- 候选包只能由手动触发的 candidate workflow 生成，不得直接创建正式 Release。

### 0.4 里程碑依赖与并行

- M1 是 M3 的硬前置（依赖升级先行）；M4 动工前须完成 TASK-000 的 v2.4.6 复核。
- M2、M5 与 M1 无依赖，可并行推进。
- M6 依赖 M1–M5 全部收口。
- 同一里程碑内任务可并行，但 M3 的 TASK-007/008（事务持久化与恢复）应先于 TASK-009～012 合并，避免新安装入口建立在不可恢复的事务上。
