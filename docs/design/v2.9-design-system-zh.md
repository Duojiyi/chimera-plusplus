# Chimera++ v2.9 设计系统与逐屏规格（中文）

> 状态：设计稿阶段。**尚未落地到前端代码**——按用户要求，前端改动须在设计经用户审阅批准之后才开始。
> 画布：Pencil `untitled.pen`；每屏 1140 × 816（默认与最小窗口尺寸）；深色为主，另出浅色模式与令牌规范页。
> 本文档是设计稿与前端实现之间的合同：颜色、字号、间距、组件与每屏结构以本文为准。

---

## 1. 设计方向：Signage（站牌语言）

产品母题来自**城市轨道交通的线路牌**——它天然解决本产品的两个核心问题：

1. **「我在哪条线上」**：线路身份用一条 14×3 的线路色横杠表示，不靠 logo、不靠缩写。
2. **「这条线通不通」**：连通性用状态色表达，与身份色分离。

三条硬规则（越界即视为设计缺陷）：

| # | 规则 | 反例（明确禁止） |
|---|---|---|
| 1 | **同一屏只允许一种饱和色**，且只用于健康状态 | 侧栏同时出现 7 种彩色徽标；蓝色渐变主卡 |
| 2 | **选中态用反白**（浅底深字），不用彩色渐变、不用彩色描边 | 渐变蓝「当前线路」大卡 |
| 3 | **不为「容器感」加边框**，只画分隔线；卡片只给真正成组的可交互对象 | 卡片套卡片、每行一个圆角框 |

补充纪律：

- 装饰性阴影、视差、弹跳动效一律禁止；动效只用于表达状态变化（160ms ease-out 位移/淡入，120ms 线性面色）。
- 四站轨道母题**只能用于真实链路**（Codex → 代理 → 上游 → 模型），**不得**复用成 KPI 条模板（v2.8 的用量页、Codex 管理页就是滥用案例）。

### 2.4 状态色

| 令牌 | 深色 | 浅色 | 语义 |
|---|---|---|---|
| `ok` | `#4aa76a` | `#227a41` | 正常 / 已连通 / 当前生效 |
| `warn` | `#c9903a` | `#896018` | 注意 / 额度偏低 / 需重登 |
| `bad` | `#dd6a63` | `#a1372f` | 失败 / 超时 / 已过期 |

状态色**永远**与文字或图形同时出现（色点 + 文案），不单独用颜色传达信息（WCAG 1.4.1）。

**第二轮审计补充的铁律**：`ok` 绿**只允许**表达「可用 / 连通 / 已启用」这一族语义。**禁止**用绿表达「失败次数」「下降」「冲突」——这些一律用 `warn` 或 `bad`。v2.8 和本设计稿第一版都犯过「用成功色画失败 9 次」的错。

### 状态设计（统一规则）

| 状态 | 做法 |
|---|---|
| 空态 | 左对齐说明 + 主操作，**禁止**居中大框（v2.8 的错误示范） |
| 错误态 | 就地红边条（左 2px `bad`）+ 一句原因 + 重试按钮；**不**依赖 4 秒 toast |
| 加载 | 骨架条 3 行（`#ffffff0a` 高 10），**不**用转圈遮罩 |
| 危险操作 | 行内红字 + 二次确认（仅删除/卸载类），切换类**不**二次确认，改为可撤销 |

## 4. 信息架构

v2.8 的问题：侧栏 18 项平铺，且用自造双字母缩写（CC/CD/Gm/OC/Pi/Om/Gk）当图标——像错字。

v2.9 改为 **工具切换器 + 该工具的导航**：

```
标题栏 40px   Codex ／ 线路                        [搜索 Ctrl K]  [— □ ×]
侧栏 216px
  ┌ 工具切换器
  │   ▌Codex            （▌= 3×16 线路色竖杠）
  │    当前工具  ⌄
  ├ 工作区        线路 · 官方账号 · 提示词 · Skills 与 MCP · 用量
  ├ 本机          Codex 管理 · 外观 · 配置体检
  └ 会话 · 设置（固定在底部，跨工具常驻）
```

- **切换类工具**（Codex / Claude Code / Claude Desktop / Gemini CLI / Grok Build）：有「当前线路」，导航含「账号」，界面有单选与「当前」徽章。
- **累加类工具**（Pi / oh-my-pi / OpenCode）：**没有**当前项，条目用开关启停，界面顶部有一条说明带明说这一点。两种模式必须一眼可分。

## 7. 未决问题（需用户拍板）

详见 `docs/design/audit-v2.9-2026-11-10.md` §4（D1–D9）。三条最主要的：

1. **版本号**：设计稿顶栏写 `2.9`，而仓库实际是 `2.8.10`，文档基线却按 `2.9.0/2.9.1` 写。下个版本到底叫 2.8.11 还是 2.9.0？
2. **是否保留「四站链路」**：它是本产品最有辨识度的元素，但也最容易被看成装饰。建议保留（真实链路信息），但**只准出现在当前线路卡**，其它页面禁止复用。
3. **切换是否要二次确认**：现版本是黑盒直接切。设计稿给的是「可撤销的即时切换 + 切换中进度」；只有「会重启 Codex」时才弹确认。是否接受？

## 8. 落地前置条件（硬门禁）

**本设计未获用户书面批准前，`src/**` 一个文件都不允许改动。** 批准后按以下顺序落地：

1. 令牌层：`src/theme/tokens.css` 引入本文 §2 的全部令牌（含浅色映射），旧变量保留别名避免一次性大改。
2. 原子组件：`src/components/ui/` 新增 `error-state` / `empty-state` / `skeleton` 三件套 + 线路色横杠组件 + 统一按钮/开关/徽章。
3. 外壳：`src/ChimeraApp.tsx` 的侧栏与标题栏按 §4 重写（该文件已 7577 行，**必须同时拆分**）。
4. 逐视图替换：按 01→19 顺序，一个视图一屏，每屏落地后跑一次像素对照。
5. 全部落地后执行全项目双盲审计 + 编译验证 + dev 预览。
