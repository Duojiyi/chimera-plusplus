## 结论

这一版方向成立、完成度高：签名元素「线路站牌」真实承载路由状态，颜色 token 零原始色值，1015 个可见文本节点除禁用态外全部过 AA；但输入类控件的焦点态不满足 WCAG 2.2 焦点外观（红线 9），本阶段**不可交付**。修掉 1 个 P0 和 5 个 P1 即可交付，不需要重做。

### 重点维度核对

**1. 签名元素与"新颖、好用、高端、不落俗套"**

- 签名元素是「线路站牌」：线路页顶部一块深色站牌（浅色主题下 #1A1E24，与页面 16.46:1），左侧线路徽标 +「DeepSeek」，右侧实测读数，下方四站路径条「Codex → 本地代理 → api.deepseek.com → deepseek-v4-pro」，每站两行真实状态（CLI 0.61.0 · 运行中 / Responses → Chat / HTTP 200 · 已连通 / 默认模型 · 128K 上下文）。它有两个配套：贯穿侧栏、列表、编辑页、回执的 2 字线路徽标（第三方方形、官方圆形），以及带「新值（原值）」和撤销的回执。
- 是否成立：成立。它编码的是真信息而不是装饰，替代了旧版不承载数据的点阵地球；故障时断点落在出错的那一站并直接给修法（DS `nDHJV` 超时变体：「10 s 无响应 · 请检查地址或网络」，后一站「未到达」）；「需重启 Codex · 运行中，仍在用旧线路」这种诚实状态，是只有认真做过的人才会做的。
- 认知负担：状态层面低（一眼看颜色与「正常 / 失败」）；词汇层面偏高，隐喻词「换乘」漏进了按钮和回执（P2-1）；四站结构固定，不经本地代理的线路怎么画还没有定义（P3-15）。
- 三份清单：A2 三簇未命中（底色 #F0F3F5 为冷灰，OKLCH H236、C0.004；无衬线；无单一酸性强调；无发丝线 + 零圆角）。禁用色域未命中（堇紫 H298 只是 6 个身份色之一，不是主色；画布里没有任何渐变填充）。调研俗套 C1-C16 全部未命中（C16 行操作常驻，不靠悬停；C12 地球被路径条取代；C8 浮层是 1px 边 + 12px 模糊，未到 16px）。critique §5 AI 产物清单未命中（没有 eyebrow 脚手架，没有 01/02/03，没有玻璃，圆角上限 8px，没有伪造的营销数字与元文案）。
- 与 research-awards 标杆对照，强在：Flighty 式「状态先于装饰」（站牌）；Claude Code 式「先预告再许可」（写入预告带目标文件绝对路径与逐行 diff）；Geist 式颜色 token 纪律（颜色三层映射、零原始色值）；Linear 式单行多级墨色（text-1 / 2 / 3 在一行内混用）；Raycast 式键位提示（Ctrl K / Ctrl F / Esc）。
- 差在：外壳（黑底主按钮 + 1px 描边次按钮 + 灰侧栏左竖条 + 4px 圆角）与 shadcn / Vercel 默认皮几乎同款，拿掉站牌就没有 Chimera++ 独有的东西（P2-11，品味判断）；间距 token 纪律远不如 Geist（P1-3）；身份色与状态色同明度同饱和，没有做到 Linear / Geist 那样「强调只留给状态」（P2-2）；站牌里名称与读数同为 28px / 700，不如 Flighty 只把一个读数推到最大（P2-10，品味判断）。

**2. 信息架构**

- 结构：侧栏 = Codex（工具行 + 9 个能力项：线路、官方账号、提示词、Skills 与 MCP、会话、用量、运行时、外观、配置体检）+「其他工具」（Claude Code、Gemini CLI、OpenCode、Pi 为叶子项）+ 添加工具 + 设置。Codex 与其他工具的能力不对称用「展开的组 vs 叶子项」表达，清楚且不割裂。其他工具没有子项，不会点进空页；「外观」在产品策略关闭皮肤时有空页风险（P3-16）。
- 切换类与累加类（不悬停）：侧栏行尾，切换类放当前线路徽标（Codex「DS」、Claude Code「智」、Gemini CLI「官」），累加类放启用计数胶囊（OpenCode「3/5」、Pi「2/3」）；组件层，切换行 =「切换」按钮 +「当前」胶囊，条目行 = 开关 + 铅笔，条目表头写「已启用 3 / 5 · 可同时启用多条」；页头副标题直接写「Codex 同一时间只走一条线路」。静止状态下可分。「3/5」要先学会才懂（P3-14）。
- 缺口：其他工具「维持现状」的会话在导航里无处安放（P1-5）；文案里的「变更记录」在导航里不存在（P2-14）；工具行没有「当前」态（P1-1）；Codex 工具行是组头、其他工具行是链接，同一组件两种行为（P3-17）。

**4. 凭据安全在界面上可见**

- 密钥默认遮蔽：`sk-••••••••••••••••c81e`（前缀 + 末 4 位），「显示」后 10 秒自动隐藏；字段下与写入预告里两次写明「已保存在系统凭据库，不写入 config.toml」「密钥只存在系统凭据库，不写入任何文件」。
- 官方令牌永不显示：官方行只显示遮蔽邮箱与套餐（`li***@gmail.com · Pro`）和「ChatGPT 登录」，本阶段没有任何令牌字段（官方线路编辑页未画，第 2 阶段复核）。
- 危险操作：删除有确认（范围、后果、将修改的绝对路径、先备份到、默认焦点取消）；切换有回执撤销。

## P0

**[P0-1] 输入类控件的焦点态不满足 WCAG 2.2 焦点外观（红线 9）**

- 位置：DS · 组件 `apJK1` › 表单控件 `M6hUs` › 状态 · 输入框 · 续 › 焦点 `ovi5j`（覆写 `bRFoa`）；02 线路编辑 `BK7bx` › 请求地址 `AKR5E/bRFoa`（本帧处于聚焦状态的字段）。同一套输入框描边被密钥输入 `p3XlGl`、下拉 `cAbRL`、筛选框 `rsbgY`、映射表输入复用。

## 做对的地方

1. **签名元素承载真信息。** 站牌四站各带实测状态，故障时断点落在出错的那一站并给修法（「10 s 无响应 · 请检查地址或网络」，后一站「未到达」），「需重启 Codex」态写出「运行中，仍在用旧线路」（`vElSw`、`nDHJV`）。它替代了旧版不编码任何数据的地球，高度 160px。
2. **写入预告。** 编辑页右栏常驻：目标文件绝对路径 `C:\Users\lin\.codex\config.toml` + 逐行 diff（− / + 前缀，不只靠红绿）+「密钥只存在系统凭据库，不写入任何文件」+「写入前自动备份」（`HFyPq`）。把调研 G7「先预告再许可」做成了编辑流程的一部分，而不是事后的弹窗。
3. **撤销与差值。** 回执卡「原线路 OpenAI 官方 · 主力　延迟 182 ms（原 240 ms）」+ 撤销；线路页常驻「撤销」。新值旁列原值，用户不用记上一个状态。
4. **颜色 token 纪律。** 5 帧 fill / stroke / effect 全扫，0 个原始色值、0 个渐变；252 个变量分 primitive → semantic → component 三层，深色只替换 semantic 映射。
5. **对比度。** 1015 个可见文本节点，非禁用态全部过 AA，三张界面最低 4.79:1；焦点环对相邻底色浅色 4.65-5.09:1、深色 6.17-8.23:1；控件边框 3.26-3.67:1；灰度图下所有状态可辨。
6. **静止状态下分得清切换类与累加类。** 侧栏行尾「当前线路徽标 vs 启用计数」，行内「切换按钮 + 当前胶囊 vs 开关 + 铅笔」，表头「可同时启用多条」，页头「Codex 同一时间只走一条线路」。四个上游都没做到这一点。
7. **官方与第三方分得清，凭据不外露。** 分组置顶 + 圆形 / 方形徽标 + 认证列「ChatGPT 登录 / API 密钥」+ 站牌类型标；官方行只显示遮蔽邮箱与套餐，没有任何令牌字段；过期账号在行内给原因与「重新登录」。
8. **密度与外壳占比。** 1140×816 下站牌 + 9 条线路同屏，不滚动；标题栏 40px 只占窗口高度 4.9%（旧版外壳 27%）。
9. **中文排版底线全部守住。** 段落 15px / 1.7、每行 17-27 字；中文只用 400 / 700；零字距；拉丁在前的字体栈；技术名词两侧手工空格；中文引号。
10. **状态覆盖。** 线路行 7 态（默认、悬停、当前、测速中、超时、切换中、键盘焦点），按钮 6 态，空 / 加载 / 错误三态；错误态文案给出原因、范围与出路（「下面显示的是 09:38 读取的结果」+ 重试 + 打开 config.toml）。
11. **平台与动效。** Windows 标题栏按钮 46×40、关闭悬停 #C42B1C、窗口 8px 圆角 + 1px 半透明外沿（`$shell-edge`）；动效 100-240ms，出场 = 进场 × 0.7，减弱动效「直接切到终态，保留文字差值」。
12. **文案干净。** 447 条去重文案：无单个破折号、无感叹号、无营销百分比、无元文案、无推广位；示例数据跨帧自洽。
