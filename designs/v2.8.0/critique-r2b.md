# Chimera++ v2.8.0 第 3 阶段界面评审（评审 B，R2）

> ⚠️ 单通道评审（原因：评审 B 独立执行，与评审 A 互不可见；画布只读，没有运行时 DOM 与无障碍树）。机械项（resolveInstances 全量节点扫描：token 绑定、字号/行高分布、两套主题逐文本对比度、裁切、控件尺寸；25% 缩放导出）已跑，主观项未经第二视角交叉验证。
> 取证方式：21 个 frame 全部以 1x 导出 PNG 逐张看过；对比度用 WCAG 2.x 相对亮度公式在画布脚本内计算（resolveVariables 按 frame 主题解析），不是目测估算。
> 未读取任何设计代理输出、迭代日志或其他评审文件。上一位评审 B 的草稿笔记已逐条复核，复核结果并入正文（草稿里「17 个 frame / 08D 等不存在」已过时：本轮 21 个 frame 全部存在）。

## 结论

**不可交付。** 有 2 个 P0（线路页筛选框 208×20、会话勾选框 16×24，点击目标都 < 24px，命中红线 10），另有 11 个 P1：跨页数据互相打架（会话数、线路归属、模型用量三组口径各说各话），外壳去掉产品名后没有识别度（「高级感」未达成），深链确认框没给绝对路径，还有两处 brief 必需流程没有画面。

## P0

### [P0-1] 线路页筛选框只有 20px 高，低于 24px 点击目标下限，键帽顶满整框
位置：组件实例 `V9zONU/iEHey`「筛选」（页头 · 操作区），出现在 `XP7zo` 13C、`isuQm` 13E、`Im4hp` 14、`d0ZWUN` 14D、`N0xze` 15、`A7NjU` 15B；DS 状态矩阵 `SBZnp`「筛选框」一行同样是这个高度，是组件级缺陷。
现状：`width 208`，未设 height，按内容撑成 **208×20**；子节点「键帽」`eLYsa` 高 20，与外框同高，上下没有内边距，截图里键帽边框与输入框边框重叠。同一行「全部测速」「添加线路」是 32px（`size-control`）。`size-control-sm` 是 28，没有任何 `size-*` token 等于 20。
影响：按 preflight 红线 10（< 24×24）直接命中。WCAG 2.5.8 的间距豁免在上下无邻近目标时或许能勉强成立，但本项目 brief 写明「点击目标 ≥24×24」，且这是 Ctrl F 的落点，高频使用。视觉上也是全线路页唯一一处「矮一截」的控件。
建议：筛选框 `height` 设为 32（与 `size-control` 一致），padding 用 `[0, $space-6, 0, $space-10]` 不变；键帽高度保持 20，靠 `alignItems: center` 居中，上下各留 6px。改组件一处即可覆盖 6 帧。

### [P0-2] 会话列表勾选框 16×24，宽度不足且与整行点击区紧贴
位置：`d43iy` 07、`h85mU` 07B 会话列表每行的「勾选」frame。
现状：勾选区 **16×24**；它的右侧紧邻整行（行点击打开详情），两个目标相邻，24px 圆的间距豁免不成立。勾选框内部的文字标签被裁掉（实例里残留组件默认文案「修改前先备份」「同时导出会话」，被 clip 隐藏）。
影响：多选是批量导出 / 删除的唯一入口，鼠标用户容易点成「打开详情」；屏幕阅读器会读到残留的组件默认文案，或者没有可读名称。
建议：勾选命中区扩到 32×42（与 `size-row` 42 同高），视觉方框保持 16；无障碍名称写成「选择：{会话标题}」，删除残留的组件文案或设为 `enabled:false`。

## P1

### [P1-1] 外壳没有识别度，签名元素只在线路页出现（「高级感」未达成）
位置：外壳组件 `ZYbq7` / 侧栏 `HdG9j` / 标题栏 `wnYKj`，全部 21 帧。
现状：石墨框 `chrome-bg #171C21` 占 1140×816 窗口的 22.9%，与内容面 `#FDFDFE` 对比 16.87:1，是全界面最强边界；内容面是白色圆角面板。站牌签名只在 12、13C、13E、14、14D、15、15B 这 7 帧出现；07、07B、08、08D、09A、09B、10、10B、11、11B、13A、13B、13D、13F 这 14 帧没有任何只属于本产品的元素。逐项对标证据见上一节。
影响：违反用户明确约束「不能落俗套，而且要看起来高级高端」（仲裁链第 3 位，高于 register 默认与审美偏好）。
建议（≤3 个杠杆，便于归因）：① 把站牌语言延伸成全局元素：标题栏胶囊改为一条迷你站牌（当前工具 → 当前线路 → 延迟），非线路页也能看到「这条线在跑」；② 外壳对比度降下来：浅色主题侧栏改用 `bg-base` 系的冷灰，或把石墨框与内容面对比压到 3:1 左右，让内容成为最强层；③ 08 用量的每日柱状图改为按线路色（`id-*`）堆叠，和站牌、线路徽标同一套色码，让数据页也「长得像 Chimera」。

### [P1-2] 会话数量三处口径互相矛盾（862 / 96 / 1284）
位置：`d43iy` / `m8LcdJ` 页头 `qXz42/RYgdm`；`w5nfgh` KPI `K9I22g/NHXyh`；`JoNru` 进度 `e3zMu`；`A1i7aN` 后果说明 `v0jMka`。
现状：
- 07 筛选条件是「近 7 天」，页头写「当前显示 Codex 862 条」；08 同样「近 7 天」，写「对话 96 个」。同一时间窗、同一个工具，862 ≠ 96。
- 13D 卸载确认说 `C:\Users\lin\.codex\` 里有「1284 条会话记录」；07 页头说 1284 是 Codex、Claude Code、Gemini CLI、OpenCode **四个工具合计**，Codex 只有 862。
- 13B 用量汇总「已读取 412 / 1284 个文件」；用量只属于 Codex，不该读其他工具的 422 条会话文件。
- 附带：1284 同时还是 08「总词元 1284 万」，同一个数字被复用成三种含义，读起来像编造。
影响：违反「数据要真实可信、前后一致」；卸载确认框里的数字是用户做破坏性决定的依据，数错了等于误导。
建议：定一套口径并在各处一致：Codex 全部会话 862；近 7 天 Codex 对话 96（07 若按近 7 天筛选应显示 96）；13D 写 862；13B 写「已读取 x / 862」；把总词元换一个不与会话数相同的值。

### [P1-3] 会话的线路归属与切换记录冲突
位置：`d43iy` 会话列表与详情 `yw2Kd`；`bgtBk` 备份表 `K4A7o0`、`L3mX4l`；`A7NjU` 最近切换 `MMTSi`、`DLdYd`；`N0xze` 回执条。

- 「修复 config.toml 迁移时丢失 profile 的问题」走 DeepSeek，时长 1 小时 12 分、最后活动 14:20，即约 13:08 起就在用 DeepSeek，而 DeepSeek 14:20 才成为当前线路。
