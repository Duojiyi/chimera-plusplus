## 1. Design Read

为了让**每天多次在官方账号与第三方线路之间切换的中文开发者**感到**"心里有数、敢切敢改"**，这个界面必须**把"现在走的是哪条线路、这条路径每一段是否健康、刚才改了什么、怎么退回"放在第一眼，并让 Codex 与其余 9 个工具的能力差异在导航里自己说明白**。

## 2. 三个旋钮

| 旋钮 | 取值 | product 基线 | 理由 |
|---|---|---|---|
| `DESIGN_VARIANCE` | **6** | 4 | 用户要求"新颖、高端、不落俗套"，上调 2 档。但偏离只集中在三处：当前线路"站牌"（签名元素）、线路徽标的形状编码（官方圆标 / 第三方方标）、导航兼作各工具的状态牌。外壳骨架（标题栏 + 侧栏 + 内容层）、列表、表单都保持可预测，因为这是每天用八次的工具，版式实验会直接拖慢切换。再往上（7+）意味着非常规布局，可用性代价超过收益。 |
| `MOTION_INTENSITY` | **3** | 3 | 只保留状态动效：换乘时路径条的线路色沿线从 Codex 站推到模型站（240ms ease-out），徽标落位 180ms，回执进出。无入场编排、无循环动画。 |
| `VISUAL_DENSITY` | **6**（分层） | 6 | 同屏分层：导航与线路列表走密（≈7：42px 行、首屏 9 条线路），站牌走疏（≈4：大字名称 + 一个读数 + 一条路径）。对外换算：产品页 ≈55% 内容占比。 |

## 3. 方向选择

**选定：A「换乘」为骨架，融合 C「回执」的"写入预告 + 撤销"作为信任机制。B「座舱」不采用，只借一个小点。**

理由：
- A 的"线路即身份"是唯一能同时回答 brief 两个硬问题的方向：切换类 = 只有一个"当前"站牌槽；累加类 = 没有站牌、只有已启用条目的计数。它在每一屏都可见（徽标出现在导航、列表、编辑器、日后的用量图例与会话筛选），不是只在某个动作后才出现。
- C 补上 A 没回答的"改了什么、怎么退回"：切换后给出"新值（原值）+ 写入的文件 + 备份编号 + 撤销"；编辑器右栏直接显示将写入的 config.toml 差异与绝对路径（研究 §4-4 写入预告、G7）。
- B 的来源着色需要学习成本，深色优先 + 青 / 品红最容易滑进 C2 / C11 与 `tokens.md` §4.5。只借"推导值要标出来"：协议选"自动"时就地写出推导结果，不另起颜色。
- 上游调研 §4 的八条差异化建议，本方向逐条对应（见 §6）。

被拒方案：
- 纯 A（只有徽标 + 换乘动效）：静态画面缺信任表达，切换后"改了哪里"不可见。
- 纯 C（单色墨 + 印章）：签名只在操作之后出现，静态首屏没有识别度；印章朱与危险红同族，风险大。
- 保留地球：不承载信息（现状诊断第 1 条），拒绝。

## 4. A1 方案

### 4.1 世界来源与色相逻辑

地铁 / 公共交通导视：浅色站台面 + 石墨色站牌 + 白字 + 彩色线路圆标 / 方标。颜色只属于"线路身份"与"状态"，界面框架本身是单色的。站牌是整屏唯一的深色物件，所以它天然成为第一视觉（G1）。

### 4.3 字体角色（2 个）

1. **界面字体栈**：`Overpass, "PingFang SC", "HarmonyOS Sans SC", "MiSans", "Microsoft YaHei UI", "Microsoft YaHei", sans-serif`。拉丁与数字走 Overpass（Delve Withrington 对美国公路标志字体 Highway Gothic 的屏幕化诠释，OFL，不在反射拒绝清单上），中文走系统栈。画布上中文与中英混排节点用 Noto Sans SC 代表系统中文栈；纯拉丁 / 纯数字节点（线路徽标字符、延迟读数、版本号、计数）用 Overpass。中文只用 400 / 700。
2. **机器文本**：`Overpass Mono`，只给请求地址、模型 ID、文件绝对路径、密钥末 4 位、config 差异。与界面字体同一设计源，混排时笔画气质一致。

说明："Noto Sans SC"在画布上只是系统中文栈的替身，与 Overpass 属于同一个字体栈的两半（按字符回退），不是第三种字体选择；等宽是第二个角色。满足 preflight 红线 1（单页 ≤2 种）。

（字体比选记录见 §5.1。）

### 4.5 签名元素：线路站牌（当前线路牌 + 路径条）

当前线路显示为一块石墨色站牌：左侧是这条线路的彩色徽标，大字线路名，右侧是状态与一个延迟读数；下方一条线路色的**路径条**标出请求真实经过的站：`Codex → 本地代理（协议转换，仅在需要时出现）→ 请求地址 → 模型`，每站两行标注（站名 / 版本、转换方向、实测延迟、模型角色）。失败时断点落在出错的那一段（虚线 + 危险色 + "超时"）。换乘时线路色沿路径条从 Codex 站推到模型站。

它为什么是这个产品独有的：路径条编码的是 Chimera++ 自己写进 config 的真实链路（直连还是本地代理、转换成什么协议、打到哪个地址、用哪个模型），换一个产品就不成立；它同时取代了不承载信息的地球。

配套（同一套身份系统，不是第二个签名）：线路徽标。第三方线路 = 线路色实心方标 + 2 字简称；官方账号线路 = 石墨实心圆标；工具 = 描边方标。形状 + 颜色 + 文字三重编码，灰度下仍可分。

### 4.6 交互签名

Ctrl K 全局命令（"切换到 Kimi""全部测速"）+ 列表内直接打字筛选（避开输入框与输入法组字）+ ↑↓ Enter 切换 + 每次写入都带"撤销"。

### 5.1 字体比选

2026-09-27 在画布上用同一组样本（"DeepSeek 182 ms"大字、"gpt-5.5 · 0.61.0 · 3/5 · 1.2 s"小字、同尺寸中文"当前线路 / 延迟 模型"、线路徽标"DS"）并排试排了 5 款拉丁字体与 4 款等宽，试排后已删除临时画板。

|---|---|---|
| Overpass | 大字与徽标有公路 / 站牌标识气质，数字开阔；小字略窄 | **选用**（签名语义最贴合"换乘"） |

## 7. Token 与对比度

### 7.1 架构（画布变量共 251 个）

- **Primitive**（`p-*`）：中性阶梯 `p-n-{L×1000}`，步号即 OKLCH 明度（例 `p-n-235` = L 0.235），色相 250 / 255、色度 0.001-0.014；线路色 `p-line-*`；状态色 `p-green/amber/red/blue-{L×100}`；透明墨 `p-ink-a*`、`p-black-a*`、`p-white-a16`；Windows 关闭按钮红 `p-win-close`（平台常量）。
- **Semantic**：只有这一层带 `mode: light / dark` 主题映射，例如 `bg-base`、`bg-surface`、`bg-plate`、`text-1..3`、`border-control`、`focus`、`success-fg/bg/border/solid` 等；线路身份 `id-cobalt / violet / magenta / teal / moss / ochre`（不分主题）。
- **Component**：只引用 semantic，例如 `btn-primary-bg → action-primary`、`input-border → border-control`、`nav-bg-active → bg-base-active`、`plate-fg-1 → text-plate-1`、`tag-current-bg → action-primary`。组件节点只使用 component 或 semantic 变量，不出现原始色值。
- 数值：间距 `space-2…64`（4px 基数）；圆角 `radius-control 4`（按钮、输入、方形徽标，Windows 11 控件惯例）、`radius-panel 8`（站牌、面板、浮层、窗口）、`radius-pill 999`（圆标、胶囊）；字号 `text-xs 12 / sm 13 / md 14 / base 15 / lg 18 / xl 22 / 2xl 28 / 3xl 32`；行高 `lh-body 1.7 / lh-ui 1.4 / lh-title 1.3`；尺寸 `size-titlebar 40 / size-sidebar 216 / size-row 42 / size-control 32`；动效 `dur-instant 100 / fast 150 / base 200 / slow 240`，`ease-out cubic-bezier(0.22, 1, 0.36, 1)`（沿用 DESIGN.md）、`ease-in-out cubic-bezier(0.65, 0, 0.35, 1)`；字体 `font-cjk / font-latin / font-mono`。

### 7.2 关键取舍

- 深色中性色第一版算出来是 `#101316`（近黑，贴近 C2），已整体上调：深色底 L 0.225（`#191C1F`）、纸面 0.255（`#1F2328`）、悬停 0.285、选中 0.315。
- 浅色警告圆点第一版 `#E69D12` 对白底只有 2.25:1（不过 3:1 非文本门槛），改为 `#C98000`（3.14:1）；警告文字另用 `#915C08`（5.5:1）。
- 线路色按色相微调明度（0.54-0.56），同时满足"白字 ≥4.5:1"和"深色纸面上形状 ≥3:1"；堇、洋红在 L 0.54 时对深色纸面只有 2.9:1，调到 0.56。

## 9. 界面决策

### 9.1 外壳（01 / 01D / 02 共用）

- 分层照 Windows 11：标题栏与侧栏同在"站台层"（`bg-base`），内容是"纸面层"（`bg-surface`），左上 8px 圆角 + 上、左 1px 边。窗口 8px 圆角 + 1px `shell-edge` 外沿（透明窗口、无系统阴影时，这条线是桌面与应用的唯一分界，DESIGN.md 已有此要求）。
- 标题栏 40px：左字标，正中全局命令框（`Ctrl K`），右侧 46×40 窗口按钮（最小化 / 最大化 / 关闭，关闭悬停为系统红 `#C42B1C`）。不放当前线路：导航里已经有，站牌也有，放三处是噪音。
- 侧栏 216px："工具 × 能力"。Codex 组 9 项能力；"其他工具"每个一行，尾部显示状态：切换类 = 当前线路小标（Claude Code "智"= 智谱 GLM；Gemini CLI "官"= 官方登录圆标），累加类 = 已启用 / 总数（OpenCode 3/5、Pi 2/3）。演示稿启用了 4 个非 Codex 工具，用来证明 IA 能容纳多工具；默认状态只有 Codex，其余由"添加工具"启用。
- 当前能力项：3px 指示条 + 粗体 + 底色（形状与字重双变化，不只是颜色）。

### 9.2 01 线路 · Codex

- 页头第一句写模式："Codex 同一时间只走一条线路 · 共 9 条"（研究 §4-3：工具页头第一句直接说模式）。主操作只有一个："添加线路"；"全部测速"为次按钮；"筛选线路"输入框带 `Ctrl F`，同时支持焦点不在输入框时直接打字筛选（规格见 §4.6）。
- 站牌（签名）：DeepSeek，路径 Codex CLI 0.61.0 → 本地代理（Responses → Chat）→ api.deepseek.com（HTTP 200）→ deepseek-v4-pro（128K）。读数 182 ms + "正常 · 2 分钟前测速"。

- 列表：官方账号组置顶（3 个账号，每个账号一条线路，**多官方账号 IA 选"每账号一条线路 + 官方组置顶"**，理由见研究 §2.5：换号与换线路是同一个动作，与托盘一致，额度可并排比较），第三方线路组 6 条。备用账号演示"登录已过期"：副行警告色 + 延迟列"需登录" + 行操作换成"重新登录"，令牌本身在任何地方都不显示。

## 10. 自评：仍不满意的地方

1. 画布无法逐字回退字体：含中文的字符串（如列表里的"OpenAI 官方 · 主力"）里的拉丁字符用的是 Noto Sans SC 的拉丁字形，而纯拉丁节点（站牌大字"DeepSeek"、徽标）用 Overpass，同一个词在站牌与列表里字形不同。生产环境由字体栈解决，但评审只看画布，可能会被读成字体不统一。
2. 深色站牌是"更深的嵌入块"，与纸面只有 1.21:1，靠 1px 边和内容撑起边界；它在深色里的第一视觉强度弱于浅色版。备选是深色里改为略亮的抬升面，需要在第 2 轮对比。
3. 线路色在深色纸面上的形状对比只有 3.09-3.24:1，刚过线，余量小；第 7 条及以后的线路会复用颜色，身份以简称为准，这条规则画布上还看不出来。
4. 交互签名（`Ctrl K` 命令面板、直接打字筛选、↑↓ Enter 切换）只在标题栏和筛选框里露了入口，面板本身留到第 3 阶段的状态页。
5. 02 未画"高级配置"折叠行，也没有保存中 / 部分成功 / 获取模型失败等编辑器状态；映射表缺维护者草稿里的"指令"列。
6. 完整回执只在 DS 里，01 只展示了收起后的回执行；没有画"切换中"整屏中间态与"需重启 Codex"的站牌状态在屏上的样子（DS 有组件变体）。
7. 1440×900 伸缩未验证：内容区目前是单列列表，宽窗口下站牌和列表会拉得很长，可能需要限制列表最大宽度或在右侧加检查器。
8. 侧栏"其他工具"的尾部状态没有文字标签，第一次使用时"3/5"要靠悬停提示或工具页页头解释；需要评审确认是否足够自明。

## 18. 外壳探索：α 浅色外壳 / β 石墨外壳（用户约束"不能落俗套，要高级、高端"）

两张探索稿都放在 01 下方（y 3736），内容与 01 完全相同，只换外壳与强调色的分配，便于并排比较：

| | 探索 · 外壳 α `YgQjz`（落选，保留） | 探索 · 外壳 β `Z4dCU`（选定） |
|---|---|---|
| 外壳 | 标题栏、侧栏与内容同属浅色（`bg-base` 站台层），内容纸面靠 1px 边分开 | 标题栏与侧栏是一整块石墨框 `#171C21`，浅色内容纸面嵌在框里，左上 8px 圆角 |
| 主色 | 当前线路色（DeepSeek = cobalt）兼任主按钮色 | 固定品牌钢蓝 `#006AA0`，只给动作：主按钮、行内"切换"、"当前"标签、开关与复选 |

选 β 的理由（按重要性）：
1. **签名贯穿外壳**：石墨框与站牌同一材质，侧栏干线（当前线路色）→ 站点圆点 → 站牌色带是一条连续的视觉线，"线路站牌"不再是页面里的一张卡片，而是整台软件的语言。α 里站牌仍是纸面上孤立的一块深色。
2. **语义分离**：β 里三种颜色各管一件事，品牌钢蓝 = 可以按的东西，线路色 = 身份，饱和的红黄绿 = 状态。α 让线路色兼任主按钮色，用户换到 moss、ochre 这类低饱和线路时，主按钮会变成橄榄绿或棕色，既不像按钮也和线路身份打架；线路色一变全屏动作色跟着变，也违背"主色只给状态与当前项"。
3. **截图测试**：遮住产品名，β 读作专业桌面软件（深框浅纸是 DAW、调色、IDE 这类专业工具的材质语言），α 读作浅灰后台模板（C 类常见的"白底 + 灰侧栏 + 描边按钮"）。
4. **可用性不降**：β 框内文字全部过 AA（见下表），内容纸面仍是高对比浅底，长时间阅读的区域没有变暗。
